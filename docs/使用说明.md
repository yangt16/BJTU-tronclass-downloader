## 前提与依赖

| 依赖 | 状态 | 说明 |
|---|---|---|
| Python 3.8+ | 需要 | **自动探测**：内置 `python\python.exe` → PATH 的 `python` → `py -3`；每个候选都实际执行校验，避免撞上 Windows Store 的假 python |
| ffmpeg | **首次运行 0-首次安装.cmd 自动下载**（仅 Windows） | 写进 `bin\ffmpeg.exe` + `bin\ffprobe.exe`（约 200 MB）。仓库里不含 ffmpeg —— 单文件超过 GitHub 100 MB 限制 |
| ffmpeg（macOS / Linux） | 用包管理器 | `brew install ffmpeg` / `sudo apt install ffmpeg`，程序会自动在 PATH 里找 |
| 网络 | 需要 | 能直连校内 `tronclass.wh.bjtu.edu.cn`，**不需要 VPN** |

程序用自身所在目录做根目录（`%~dp0`），所以整个文件夹可以搬到任意位置。

### macOS / Linux 用法

入口脚本是同样的功能（同一个菜单），只是扩展名换成 `.command`：

```sh
git clone --depth 1 https://github.com/yangt16/BJTU-tronclass-downloader.git
cd BJTU-tronclass-downloader
brew install ffmpeg python3       # Linux: sudo apt install ffmpeg python3
chmod +x *.command tools/*.sh           # 从 ZIP 解压时要这一步
./0-首次安装.command
```

**不要用双击/粘贴内容的方式跑脚本**：如果双击提示"无法验证开发者"，右键 → 打开；
如果报 `zsh: event not found: /bin/sh`，说明你把脚本内容粘进了终端——请改为执行文件：

```sh
xattr -dr com.apple.quarantine .   # 解除 Gatekeeper 隔离（可选）
chmod +x *.command tools/*.sh
./0-首次安装.command
```

之后在 Finder 里双击 `.command` 文件即可；命令行等价：

```sh
./1-开始下载.command                        # 弹菜单
sh ./tools/getlec.sh                        # 跳过菜单，默认设置
GETLEC_DROPVIDEO=1 sh ./tools/getlec.sh     # 只要音轨
GETLEC_ONLY=4 sh ./tools/getlec.sh          # 只下周四
./tools/getlec.sh lists/XX课程.txt INSTRUCTOR   # 换轨
```

| 项 | macOS 说明 |
|---|---|
| ffmpeg 来源 | Homebrew 装到 PATH，程序优先找 `bin/`，再查 PATH |
| 首次双击 | 若提示"无法验证开发者"，右键 → 打开 → 允许 |
| 显示扩展名 | Finder 默认隐藏；改名后用 `ls` 确认 |
| Release 包 | 那个 zip 是 Windows 版（内含 ffmpeg.exe），Mac 请用 git clone / Source ZIP |

### 新机器部署（3 步）

```bat
:: 1. 拿到本项目（git clone 或直接解压 ZIP）
:: 2. 双击 0-首次安装.cmd  —— 找 Python、下载 ffmpeg、建 lists\
:: 3. 看到 "setup done" 就可以用了
```

`0-首次安装.cmd` 支持参数透传（都会转给 `tools\fetch_ffmpeg.py`）：

```bat
0-首次安装.cmd --check            :: 只检查 ffmpeg 是否就绪
0-首次安装.cmd --force            :: 重新下载（比如想换成完整版）
0-首次安装.cmd --dest D:\ff\bin   :: 装到别处
```

下载源按顺序尝试：BtbN（GitHub）→ gyan.dev，
单个源 10 分钟没下完、或下到 20 MB 后速度低于 0.15 MB/s 就自动换下一个。

## 手动版：自己粘地址

### 1. 在 `lists\` 里建一个清单文件

**文件名 = 课程名**。比如下XX课程，就建：

```
D:\course-notes\lists\XX课程.txt
```

不需要先建 `media\XX课程\` —— 程序会自己建。

### 2. 把播放地址粘进去

一行一个，`#` 开头是注释：

```text
https://ilesson.wh.bjtu.edu.cn/videos/outbound1/bjtu/.../20260921/101000-120500-.../ENCODER-...?ts=...&token=...
https://ilesson.wh.bjtu.edu.cn/videos/outbound1/bjtu/.../20260928/101000-120500-.../ENCODER-...?ts=...&token=...
```

### 3.（建议）先预检

```bat
python D:\course-notes\tools\check_urls.py
```

输出：

```text
[XX课程.txt]
落点: D:\course-notes\media\XX课程

状态               大小  落点
--------------------------------------------------------------------
[OK]   1000.2 MB  XX课程\20260921\XX课程_20260921.mp4  (ENCODER)
```

有 `[FAIL]` 就重新复制那一条。

### 4. 双击开始下载（按菜单选）

见 [下载模式与范围](#下载模式与范围)。

### 5. 怎么拿到播放地址

这是手动版里**唯一需要操作**的一步，约 15 秒一节。

1. Edge 打开那节回放页
2. `F12` → **Network** 面板
3. 筛选框输入 **`ENCODER`**（或点「媒体」标签）
4. **点播放**，等 10–15 秒
5. 列表里出现 `ENCODER-xxxx…`，状态 **206**、类型 **媒体**
6. **右键那一行 → 复制 → 复制 URL**
7. 粘进 `lists\<科目>.txt`

### 三条轨的区别

播放器右下角有「**音源**」按钮，可切换三个来源：

| 菜单项 | URL 里的 TRACK | 内容 | 体积 |
|---|---|---|---|
| **电脑路** | `ENCODER` | 合成画面 + 课堂音频 | 0.5–1.4 GB |
| 老师路 | `INSTRUCTOR` | 教师机位 + 教师麦克风 | ~1.6 GB |
| 学生路 | `STUDENTS` | 学生机位 + 学生麦克风 | ~1.6 GB |

**默认用 `ENCODER`**：体积最小，实测音轨有正常讲课人声（平均 −19 ~ −32 dB）。
只有转写效果明显很差时才换：

```bat
D:\course-notes\tools\getlec.cmd lists\XX课程.txt INSTRUCTOR
```

### 常见坑：Network 里没有媒体请求

**原因**：视频整段已经缓冲完，播放不再产生新请求。按 6 MB/s 算，600 MB 的课 90 秒就缓冲完。

**解决**：勾 **「禁用缓存」** → `F5` → 再点播放。或者把进度条拖到中间，强制触发新请求。

> ⚠️ 一定要**看到媒体请求再复制**，否则复制不到东西。

## 自动版：书签一次抓一门课

手动一节节复制，20 节就要点 20 次。自动版**每门课点一下书签**，一次导出整门课。

### 链路与权限（已实测）

| 步骤 | 接口 | 要登录？ |
|---|---|---|
| 1. 列出课程节次 | `GET /api/courses/<courseId>/live-activities` | ✅ 要 |
| 2. 取每节的回放轨地址 | `GET /api/activities/<activityId>` | ✅ 要 |
| 3. 换成签名直链 | `incast.../preview?previewToken=` → **302** | ❌ 不要 |
| 4. 下载 | `ilesson.../ENCODER-...?ts=&token=` | ❌ 不要 |

**结论：只有前两步需要你的登录态。** 所以在浏览器里跑一小段脚本收集地址，其余全交给本地程序。

接口形状（供以后维护用，实测于 2026-11）：

```text
GET /api/courses/<courseId>/live-activities
    ?status=&types[]=lecture_live&types[]=third_party_live
    &page=<n>&page_size=<n>
→ {"items":[{id,title,start_time,type},...], "total":17, "pages":2, "page":2}
   ⚠️ items 里【没有】replay_videos，必须再逐节查详情

GET /api/activities/<activityId>
→ data.external_live_detail.replay_videos[]
   [{camera_type: encoder|students|instructor,
     url: https://incast.../videos/<cameraId>/preview?previewToken=xxx}]
```

> 未登录访问上面两个接口返回 401 —— 所以脚本只能在已登录的页面里跑。

### 装书签（一次性）

1. 用 Edge 打开 `dist\install.html`（本地文件，双击即可）
2. 按 `Ctrl+Shift+B` 显示书签栏
3. 把页面里那个蓝色按钮**拖到书签栏**（是拖拽，不是点击），可右键改名为「抓取课程清单」

### Chrome / Edge 装书签的两种方式

| 浏览器 | 方式 | 说明 |
|---|---|---|
| Edge / Firefox | 打开 `dist/install.html`，把蓝色按钮**拖到书签栏** | 拖拽保留 `javascript:` 前缀 |
| **Chrome** | `chrome://bookmarks` → 右上 `⋮` → **导入书签** → 选 `dist/bookmarks.html` | 拖拽常丢前缀，导入最稳 |

导入后书签栏会出现「抓取课程清单」，在课程页点它即可。

> 如果点了没反应，按 F12 看 Console 是否有报错；多数是书签地址缺了开头的 `javascript:`。

### 每门课的操作

1. 打开这门课的「直播」列表页（地址里有 `/course/<数字>/live-activities`）
2. **点一下书签** → 弹框填课程名 → 选是否导出三条轨（选**取消**=只导 ENCODER）
3. 浏览器下载 `<课程名>.txt`
4. 双击下载入口 —— 它会**自动把下载文件夹里的清单收进 `lists\`** 并开始下载

完整流程就是：**点一下书签 → 双击一次**。

### 手动版（不想装书签时）

1. 打开课程「直播」列表页，等列表加载出来
2. `F12` → **Sources** → 左侧 `>>` → **代码片段** → **新建代码片段**
3. 把 `tools\scrape_course.js` 的内容**全部**粘进去
4. `Ctrl+Enter` 运行
5. 后面的弹框和导出步骤同上

> 书签是编译产物：`tools\scrape_course.js` 是源码，运行
> 
ode tools\build_bookmarklet.js` 会生成 `dist\bookmarklet.txt`（一行 javascript: 地址）
> 和 `dist\install.html`（拖拽安装页）。**改了源码要重新 build。**

### 课程还在进行：每周重跑一次

课程没上完时，列表会逐周变长（例如 17 → 19 → 21 条）。**不需要任何特殊操作**，每周重复同一步：

```text
打开课程「直播」页 → 点一次书签 → 双击下载入口
```

各环节的行为：

| 环节 | 行为 |
|---|---|
| 脚本 | 每次拉**全量**列表（自动翻页） |
| 还没开课的节 | 没有回放文件，脚本跳过并在 Console 打日志 |
| 之后出回放了 | 下次重跑时自动出现在清单里，自动补下 |
| 已下载的节 | 本地按文件判断，**整节跳过**（不联网、不重抽音轨） |

也就是说增量是自动的：**新的一节都不会漏，旧的也不会重下**。

### 清单里存的是什么

`scrape_course.js` 导出的是 `previewToken` 地址（不是最终的签名地址）：

```text
# 2026-11-09T02:10:00+00:00 2026-11-09-XX课程
https://incast.wh.bjtu.edu.cn/api/base/orgs/bjtu/captures/<hash>/videos/280740/preview?previewToken=xxx
```

本地程序在下载前会把它换成签名直链，日志里能看到：

```text
[resolve] 发现间接地址，换成直链（1 条）...
  ...preview?previewToken=bbe5  ->  ...ENCODER-xxx?ts=1794406520&token=d4f2
```

### 已知限制

`scrape_course.js` 现在**纯走接口**（列表接口自动翻页），不依赖页面 DOM，所以不受列表分页影响。

唯一的前提是：必须在**该课程的页面**里运行（地址里要有 `/course/<数字>/`），因为脚本要从 URL 里读课程 id。

如果哪天接口改版，脚本会明确报错（`列表接口失败 HTTP xxx`），而不是静默抓不到。

### 清单放哪、跑完去哪

程序**不会去扫描任何目录**（下载、桌面都不碰）。清单有两种给法：

| 方式 | 操作 |
|---|---|
| 放进 `lists\` | 把抓取导出的 txt 复制或移动进 `lists\`，文件名就是课程名 |
| 直接拖拽 | 把 txt 拖到入口图标上，只跑这一份（不必放进 `lists\`） |

**怎么拖（Windows）**：

1. 让 txt 和入口脚本同时可见：打开「下载」文件夹，再把 `D:\course-notes`
   窗口缩小或分屏，能看到 `1-开始下载.cmd`
2. 按住 txt 文件，拖到 `1-开始下载.cmd` 图标上松手
3. 弹出黑窗口开始跑这一份清单

Windows 会把被拖文件的路径作为第一个参数传进去，等价于手动执行：

```bat
D:\course-notes\1-开始下载.cmd "D:\Downloads\XX课程.txt"
```

**注意**：

- **文件名 = 课程名**：`XX课程.txt` -> `media\XX课程\`；
  浏览器重名后缀 `(1)` 会自动去掉，一般不用改名
- 拖的 txt 跑完会**移进** `har_archive\`（不是复制），想留底先自己备份
- macOS 的 Finder 拖到 `.command` 上不保证传参，建议用终端：
  `sh ./1-开始下载.command "XX课程.txt"`


成功跑完后：

- 清单归档到 `har_archive\urls_<日期>.txt`
- `lists\` 里不再保留 txt，只留 `<课程>.md` 索引

失败、或用了 `--keep-list` 时清单不归档，原地保留。

## 下载模式与范围

双击 `1-开始下载.cmd` / `.command` 后回答三次（**直接回车 = 默认**）。

**产物**（决定留下什么）：

| 选项 | 产物 | 单节占用 | 适合 |
|---|---|---|---|
| 视频 + 音频（默认） | mp4 + m4a | ~750 MB | 要转写也要看画面 |
| 只要音频（只要音轨） | 只留 m4a（下完删 mp4） | ~110 MB | **只做转写，省 6.6 倍空间** |
| 只要视频 | 只留 mp4（不抽音轨） | ~640 MB | 只要录像，音频另想办法 |

**范围**（决定下哪几节）：

| 选项 | 说明 |
|---|---|
| 下载全部（默认） | `lists\` 里所有清单的全部节 |
| 只下某一天 | 再输入日期：`20261030` 或 `20261030,20261104` |
| 只下星期几 | 再输入 `1`-`7`（1=周一 … 7=周日），如 `4` 只下周四 |
| 排除星期几 | 反过来排除，如 `2` 排除周二（实验课） |

**并发**（决定同时下几节）：

| 选项 | 说明 |
|---|---|
| 1 路 | 最稳，适合网络差/不想给服务器压力 |
| 2 路（默认） | 实测约 1.3–2 倍速 |
| 3 — 4 路 | 约 2–3 倍速；同一份清单节数多时收益明显 |

**单节加速**（决定单个文件拆几段下）：

| 选项 | 说明 |
|---|---|
| 关闭（默认） | 一个文件一个连接 |
| 4 段 | 同一个文件开 4 个连接分段下；**只补一两节时明显快** |
| 8 段 | 开 8 个连接分段下；实测 0.57 MB/s，约为 4 段（0.26）的 2.2 倍 |

> 单节加速和"并发"是两件事：并发加速"多节同时下"，单节加速把"一节"拆开下。
> 两个都开会自动限制总连接数（≤ 8），不会把服务器连接数堆爆。

连按三次回车 = 旧的"下视频和音频、全部、单路"。把 txt 拖到图标上则跳过菜单，
按默认设置只跑那一份。

```
[lists] 待下载清单 1 个:
    XX课程.txt      1 条地址 -> media\XX课程\
[getlec] LIST D:\course-notes\lists\XX课程.txt
[mode] 视频 + 音轨
[dest] 落点: D:\course-notes\media\XX课程

=== 第 1/1 节: 20260921_101000-120500  轨: ['ENCODER'] ===
  [下载] -> ...\XX课程_20260921.mp4
  [抽音频] -> XX课程_20260921.m4a
  [信息]
  上传用这个: ...\XX课程_20260921.m4a
[archive] 地址清单已归档 -> urls_20260921.txt
[archive] 清单已归档 -> urls_20260921.txt（lists 里不再保留 txt）
[archive] 已刷新下载清单 lists\XX课程.md
```

产物：

```text
media\XX课程\20260921\
├─ XX课程_20260921.mp4    1000.2 MB   录像
└─ XX课程_20260921.m4a     111.5 MB   音轨  ← 传千问用这个
```

### 按范围筛选：某一天 / 星期几 / 排除

在菜单里把范围选成 2 / 3 / 4 后，会再问一句输入：

```text
范围：2) 只下某一天
日期（8 位，如 20261030；多个用逗号）：20261030
[filter] 只要 20261030：15 节 -> 1 节
[filter] 已自动开启 --keep-list（筛选时不归档清单）
=== 第 1/1 节: 20261030_101000-120500 ===
```

| 输入（范围） | 含义 |
|---|---|
| `20261030`（只下某一天） | 只下这一天 |
| `20261030,20261104` | 只下这两天（中文逗号也认） |
| `4`（只下星期几） | 只下所有**周四**的课（1=周一 … 7=周日） |
| `2,4`（只下星期几） | 只下周一周四（适合"一周两次、一次实验"的课） |
| `2`（排除星期几） | 排除所有周一/周二的课 |

**筛选时清单不会被归档**（否则会把没处理的地址一起搬走），跑完还能继续用。

命令行等价写法（跳过菜单，直接给引擎）：

```bat
set GETLEC_ONLY=20261030
set GETLEC_ONLY=4
set GETLEC_EXCLUDE=2
:: 或者直接给 lectures.py 传参
python tools\lectures.py --urls lists\XX课程.txt --only 20261030
python tools\lectures.py --urls lists\XX课程.txt --only 4
python tools\lectures.py --urls lists\XX课程.txt --exclude 2
python tools\lectures.py --urls lists\XX课程.txt --only 20261030_10
```

`--only` / `--exclude` 接受四种写法：日期（`20261030`）、星期几（`4`，1=周一…7=周日）、完整标签（`20261030_101000-120500`）、前缀（`20261030_10`）。

> 星期几按**节次日期的星期**判断。如果某次实验课不是固定星期几，用日期更稳（先跑一次全部，再排除具体日期）。

### 按课程配置下载规则（每门课不一样）

`lists\` 里有多门课时，可能 A 课要全下、B 课只要某一天。这时用**规则文件**：

```bat
:: 双击 2-清单规则.cmd 交互式配置，或者用命令行：
python tools\rules.py                          :: 交互式
python tools\rules.py list                     :: 看所有清单和规则
python tools\rules.py set XX课程 --only 4       :: 只下周四
python tools\rules.py set XX课程 --exclude 2    :: 排除周二（实验课）
python tools\rules.py clear XX课程              :: 取消规则（恢复全下）
```

规则写在 `lists\<课程名>.rules`（和清单同名），例如：

```text
# XX课程.rules
only: 4
```

| 行为 | 说明 |
|---|---|
| 没有规则文件 | 全部下载（和以前一样） |
| 规则文件存在 | 该课按规则筛选，**清单规则优先于菜单/环境变量的筛选** |
| 跑完归档 | 有规则的清单**保留在 `lists\`**（防止把没下的日期一起归档） |
| 重新抓取清单 | 只会覆盖 `.txt`，`.rules` 不受影响 |
| 规则写错 | 打印警告并按"全下"处理，不阻断批量 |

> 抓取出来的清单每周会被新文件覆盖，但 `.rules` 会保留，配一次管一学期。

### 两个方向混着点的后果

| 先跑 | 后跑 | 最终产物 | 重新下载？ | 视频会被删？ |
|---|---|---|---|---|
| 只要音轨 | 只要视频 | mp4 + m4a | ✅ 重下视频 | — |
| 只要视频 | 只要音轨 | 只剩 m4a | ❌ 本地抽音轨 | ⚠️ **会删** |
| 都下 | 只要音轨 | mp4 + m4a | ❌ 音轨已在，跳过 | 不删 |
| 都下 | 只要视频 | mp4 + m4a | ❌ 视频已在，跳过 | — |

**要点**：「只要音频」会无条件删掉 mp4，包括你之前下好的视频。不确定以后要不要画面，就用默认的「视频 + 音频」。

## 输出规则

### 目录结构

```text
media\<清单名>\
└─ <YYYYMMDD>\
   ├─ <清单名>_<YYYYMMDD>.mp4       录像
   ├─ <清单名>_<YYYYMMDD>.m4a       音轨
   ├─ .session                     记录这一节是哪一场（防覆盖用）
   └─ .multi                       仅当这天有多节课时存在
```

### 文件名规则

| 情况 | 文件名 |
|---|---|
| 一天**一节** | `XX课程_20260921.mp4` |
| 一天**多节** | `XX课程_20261014_150100-160500.mp4`<br>`XX课程_20261014_162000-181500.mp4` |

**为什么一天多节要带时段**：课程表里一天两节真会发生（实测 10-14 有 64 分钟短课 + 115 分钟正常课）。撞名时程序把旧文件改成带时段的名字、并给目录打 `.multi`，之后新文件也带时段。已带时段的名字不会被二次改名。

### 运行时输出

每节结束后会打印整体进度和预计剩余时间：

```text
=== 第 3/7 节: 20261020_190000-205500  轨: ['ENCODER'] ===
  ...
[进度] 3/7 节  已用 6m20s  预计剩余 8m27s
```

预计剩余按"已用时间 / 已完成节数"推算，前几节可能不准，跑几节后趋于稳定。
小结里也会给出总用时。

### 体积参考

| 项 | 规律 |
|---|---|
| 录像 | 约 **4–7 MB/分钟**（实测 530–1640 kbps 都有） |
| 音轨 | 约 **1 MB/分钟**（AAC 固定 ~130 kbps） |

一节 115 分钟的课典型值：录像 0.5–1.4 GB，音轨 106 MB。

## 增量与日常维护

### 已下载的节会被跳过

**跳过是纯文件系统判断**（录像/音轨都存在且非空），不联网、不重抽音轨。
开跑前会先扫一遍落点，直接告诉你这次实际要下几节：

```text
[filter] 只要 周三：12 节 -> 6 节
[skip] 已下载 5 节，本次实际需下载 1 节

=== 第 1/1 节: 20261118_101000-120500 ===
  [下载] -> ...\XX课程_20261118.mp4     ← 只有新的这节真的下
[小结] 新下载 1 节 / 跳过 5 节 / 失败 0 节
```

19 节约 1 秒跳过完。

### 下载校验、并发进度、本次报告

**下载校验**：每节下载完成后会用 `ffprobe` 检查文件能否读出正常时长；
坏了会自动删除并在自动重试里重下，不会留下"看起来下完其实是坏文件"。

**并发进度**：并发路数 > 1 时，每节仍能看到百分比（每涨 5% 或每 3 秒刷新）：

```text
=== 第 1/3 节: 20261030_101000-120500 ===
  [下载] -> ...
  [1/3] 20261030_101000-120500  45%  35.2/78.1 MB
  [2/3] 20261104_080000-095500  60%  46.8/78.1 MB
```

**本次报告**：结束时汇总本次实际下载量：

```text
[报告] 新下载 3 节 · 录像 4200 MB + 音轨 330 MB · 用时 21m30s · 平均 3.5 MB/s
```

### 多份清单连跑：全局进度

`lists\` 里有多份清单时（批量模式），会先统计总数，再给**跨清单的全局进度**：

```text
[batch] 共 3 份清单 / 约 32 节

[batch] === 清单 1/3: XX课程.txt（约 12 节）===
...
[batch] 全局 7/32 节  已用 6m20s  预计剩余 22m
```

- 节数是**离线估算**（同一节课的多条轨按一个算），显示为"约"
- 每份清单结束仍会照旧归档、刷索引；失败一份不影响其它清单继续
- 单份清单运行时还是显示本清单的 `[进度]`

### 中断了怎么办

**什么都不用做，重新双击下载入口即可。**

- 已完成的节：跳过
- 下了一半的节：从断点续传
- 还没开始的节：正常下载

### 想让清单保留在原地

默认跑完会把清单归档进 `har_archive\` 并从 `lists\` 移走。想保留一份累积清单（不归档）时：


> 想保留清单时用命令行/引擎入口；双击 `1-开始下载.cmd` 会先弹菜单，
> 但 `GETLEC_KEEPLIST` 等开关仍会生效。

### 跑完提示与失败清单

- 跑完会**响铃**（Windows 提示音 / macOS beep），不用一直守着
- 有节失败时，失败的地址会写进 `logs\failed_<课程>_<时间>.txt`，
  并提示失败节数；直接重跑同一份清单即可（已完成的会跳过）

### 重做某几节

### 加一门新课

### 搬家 / 给同学用

**整个文件夹直接复制走就行**，不需要改任何东西：

- 程序用自身所在目录做根目录（`%~dp0`）
- Python 自动探测：不用管对方装在哪
- 对方只需要自己在 `lists\` 里建清单

拷贝时**可以不带** `media\` 和 `har_archive\`，最小可用集合：


可选：把免安装 Python 解压成 `python\` 目录一起带上，对方就零依赖了。

### 清理

| 可以随便删 | 别删 |
|---|---|
| `har_archive\` 整个目录 | `bin\`（ffmpeg） |
| `tmp\` 里的东西 | `tools\` |
| `lists\` 里跑完的空清单 | `media\`（你的课程文件） |

归档和日志只会越攒越多，可以让脚本按天数/数量清理（**默认只预览**）：


| 参数 | 作用 |
|---|---|
| `--days N` | 早于 N 天的文件（默认 60） |
| `--keep N` | 无论多旧，保留最近 N 个 |
| `--logs` | 连 `logs\` 一起清理 |
| `--yes` | 真删；不加则只预览 |

> 归档里存的是**当时的签名地址**（有时效），过期了也用不上，定期清理即可。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `[FAIL] 403` | 链接过期（`ts`/`token` 有时效） | 重新复制那一节的 URL，或重跑书签 |
| 预检全 `[OK]` 但下载卡住 | 网络拥堵 | 等等，实测出现过 2.0 MB/s（平时 6.2） |
| 中断后出现 0 字节文件 | 刚建文件就被打断 | **直接重跑**，会从 0 继续 |
| `lists\ 里还没有可下载的清单` | 没有清单或清单是空的 | 建 `lists\<科目>.txt` 并粘地址 |
| Network 里没有 `ENCODER` 请求 | 视频已缓冲，播放不走网络 | 勾「禁用缓存」→ `F5` → 再点播放 |
| 转写大量漏字 | 那节音量偏小（低到 −32 dB） | 先 `ffmpeg -af loudnorm=I=-16:TP=-1.5:LRA=11` 标准化 |
| 同一天两节互相覆盖 | 旧版本 bug | 检查日期目录里有没有 `.multi` |
| `'xx' is not recognized` 刷屏 | `.cmd` 里混了中文，或 REM 里有尖括号 | 跑 `test_cmd_ascii.py` |
| `cannot find the batch label` | `.cmd` 是 LF 换行 | 转成 CRLF，再跑 `test_cmd_ascii.py` |
| 明明成功却报 `FAILED` | 批处理运行中该 `.cmd` 被编辑过 | 别在跑批时改 `.cmd`；重跑一次即正常 |

## 设计说明

几处看起来奇怪、但都是有原因的设计。

### 为什么只认 `lists\*.txt`

早期支持过根目录 `urls.txt` 和 HAR 导入，结果是三个入口、两套配置，用户经常粘错地方（粘到根目录却以为会进科目文件夹）。

现在只有一个入口：**`lists\` 下自己建的文件，文件名就是课程名**。落点、课程名、文件名前缀全部由它推导，没有第二处配置。

### 为什么不需要 Cookie

媒体接口 `ilesson.wh.bjtu.edu.cn` **不校验 Cookie**——把浏览器那一次的请求完整抓下来看，媒体请求没带任何 Cookie。

它校验的是**请求头**：

```text
User-Agent, Referer: https://tronclass.wh.bjtu.edu.cn/,
sec-ch-ua, sec-ch-ua-platform, sec-ch-ua-mobile
```

`sec-ch-ua` 三项缺了会 403。程序里写死在 `get_media.BASE_HEADERS`。

> 早期曾误判成"cookie/session 网关"——因为拿站点根 `/` 做探针得到 403。实际上那个路径本来就 `deny all`，不能当探针用。

### 为什么分块下载

`Range` 请求按 8 MB 分块：

1. **断点续传**：中断后从已有字节数继续
2. **失败只重下那一块**（每块最多重试 6 次，指数退避）
3. **进度可见**，不会几分钟没反应

### 为什么按「日期+时段」分组而不是按目录

同一节课的三条轨可能被存在**不同目录**下（实测有 3 节出现了 `.../080000-095500-1/` 和 `.../080000-095500-2/` 两个目录）。按完整目录分组会把一节课拆成两组，导致"没有 ENCODER 轨，改用 STUDENTS"这种误导日志、白跑几轮。日期+时段才是这一节课的稳定标识。

### 为什么文件名带课程名

因为**上传工具（如千问）只显示文件名、不显示路径**。混在一堆 `.m4a` 里，`XX课程_20260921.m4a` 一眼能认出是哪门课。

### 为什么 `.cmd` 必须纯 ASCII + CRLF

这条踩了**三次**，每次都是刷屏灾难：

| 错误 | 后果 |
|---|---|
| 注释里写中文 | cmd 按 GBK 解码 UTF-8 字节，语法被破坏，变量变空、逻辑错乱 |
| REM 注释里有 `<` `>` | cmd 在 REM 行也解析重定向符，整行被拆成垃圾命令执行 → 刷屏几千行并陷入循环 |
| LF-only 换行 | `goto` / `call` 找不到标签 → `cannot find the batch label specified` |

**规则**：`.cmd` 里只写英文、注释里不出现尖括号、保存成 CRLF。中文提示全部由 Python 打印。
`.sh` / `.command` 相反：必须是 **LF** 换行（CRLF 会让 macOS 报 `bad interpreter`），已在 `.gitattributes` 里固定。

`test_cmd_ascii.py` 会替你检查这三条。

### 为什么不能在跑批时改 `.cmd`

cmd 是按**字节偏移**边读边执行批处理文件的。运行中改文件会让后续行错位，表现为乱执行、冒出 `Access is denied.`、以及明明成功却报 `FAILED`。

### 为什么子程序放在 `.cmd` 文件末尾

`cmd` 的 label 不是函数，执行流会**掉进去**。把 `:trypy` 这种子程序放在主流程中间，`goto` 跳过去后会顺着执行到它的 `exit /b`，后续步骤全被跳过。

### 为什么 `.session` 要用 `utf-8-sig` 读

PowerShell 的 `Set-Content -Encoding UTF8` 可能写入 BOM。Python 用普通 `utf-8` 读会多出一个 `\ufeff` 前缀，字符串比较静默失配——曾因此把同一节课误判成"另一节课"，白重下 607 MB。

## 已知限制

| 限制 | 说明 |
|---|---|
| **手动版要自己拿 URL** | 播放地址由服务端签名（`ts`+`token`），程序无法自己生成。想要省事就用书签自动抓 |
| **URL 有时效** | 实测 1 小时以上仍可用，但别放到第二天 |
| **只能 ENCODER 等三轨** | 平台只提供这三条流 |
| **开发环境只有 Python 能联网** | 开发环境的沙箱限制了系统加密 API，`curl.exe` / PowerShell / 默认 git 走 SChannel 会报 `SEC_E_NO_CREDENTIALS`，而普通 Windows 机器没有这个问题。为稳妥起见，程序的下载与校验全部走 Python（自带 OpenSSL），不依赖 SChannel |
| **抓取需要浏览器登录态** | 书签只能在已登录的页面里点，程序不碰账号密码 |
| **没有内置 Python** | 依赖系统已有 Python；想零依赖就把免安装版解压到 `python\` |
